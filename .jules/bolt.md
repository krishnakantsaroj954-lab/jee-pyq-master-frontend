## 2025-02-27 - Avoid O(N log N) sorts on sequences naturally ordered by outer loops
**Learning:** In layout analysis and spatial text grouping, inner loops that build subsequences from an already-sorted outer sequence will naturally produce sorted subsequences. A common anti-pattern in the codebase (such as `_word_rows` grouping) is to naively re-sort the current subsequence on every iteration to find medians or extremes. This incurs severe, completely unnecessary CPU overhead (O(N^2 log N) overall for the row assembly).
**Action:** Always check the primary and secondary sort keys of the outer generator/loop. If they guarantee the inner sequence is monotonic, compute metrics like medians via direct O(1) index lookups (e.g. `rows[-1][len(rows[-1]) // 2]`) instead of `sorted()`.
